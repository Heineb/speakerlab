# Safe Physical DSP Apply v1 Blockers

This matrix is limited to the blockers currently named in `CURRENT_STATUS.md` and the current-Beocreate mapping. The 2026-07-29 review used committed source, metadata and sanitized repository-backed fixtures only. No hardware capture or physical operation was performed.

| ID | Feature and safety significance | Current evidence | Missing evidence | Non-invasive observation | Acceptance criterion | Hardware required | Guaranteed read-only | Outcome |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| PA-01 | Fresh DSP identity; wrong mappings can make every later operation unsafe | Universal v10 XML identity and checksum request/response code | Physical response, freshness before apply and recheck after reconnect | Read checksum `0xf1` twice on an explicitly selected host | Matching checksum is repeatable, bound to the shipped map and reacquired after reconnect | Yes | Yes; exact allowlisted checksum request | Narrowed: capture contract exists; no physical observation |
| PA-02 | Routing, crossover, gain, delay and polarity readback; mismatches can damage drivers or alter output | XML addresses, legacy writes and generic `0x0a` reads | Physical readability, semantics, repeatability, units and tolerances | Read each exact mapped address twice, without mutation | Known identity, matching repeated frames, deterministic decoding, source corroboration and reviewed tolerance per field | Yes | Yes; exact address/length allowlist | Narrowed: read path and review format exist; all physical conclusions remain open |
| PA-03 | GPIO 27 amplifier mute/safe state; parameter writes must not reach audible outputs | Strong evidence for `pigs` mute commands | A proven read command and physical amplifier-state confirmation | None found in repository evidence | Read back safe state independently; later prove entry/retention/exit on dedicated test hardware | Yes | No read observation is currently proven | Retained; impossible to close with the current read-only protocol evidence |
| PA-04 | Connection-loss invalidation; stale values must never validate a new socket generation | Isolated simulator rejects stale responses | Physical reconnect behavior and production integration | Repeat identity and mapped reads before and after an independently occurring reconnect | New generation invalidates pending/cached values and requires fresh identity | Yes | Yes if the task does not trigger a restart | Retained; capture utility stops on disconnect and does not trigger reconnect/restart |
| PA-05 | Last-known-good rollback; partial application must recover while muted | Recovery state model and configuration-file rollback | Physical prior-state capture, verified writes, mute retention and rollback readback | Read-only capture can record prior readable values only | Complete prior plan plus verified ordered write/readback while confirmed muted | Yes | Partially; only prior reads are non-invasive | Retained; read-only evidence cannot prove rollback |

Related unknowns remain outside a Safe Physical DSP Apply v1 claim: positive gain/headroom, acoustic response after quantization, EEPROM persistence and restart recovery.

No blocker is closed by repository evidence alone. PA-01 and PA-02 are smaller, explicitly capturable evidence gaps. PA-03, PA-04 and PA-05 remain physical-apply blockers.
